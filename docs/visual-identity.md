# Visual Identity

This document captures the early visual and UX direction for MCP Toolkit and MCP
Inspector.

The identity should support developer trust, technical clarity, security
awareness, and infrastructure quality.

## Brand Direction

MCP Toolkit should feel:

- technical
- modern
- infrastructure-oriented
- security-aware
- developer-first
- precise and reliable

Avoid:

- generic AI aesthetics
- neon cyberpunk overload
- crypto startup visuals
- childish AI mascots
- chatbot-centric patterns

Useful references:

- Linear
- Raycast
- Warp
- Retool
- browser DevTools
- Postman
- Insomnia

## UX Principles

The product UX should feel:

- clean
- fast
- readable
- technical but approachable
- visual without being noisy
- focused on debugging workflows

Avoid:

- enterprise dashboard overload
- cluttered interfaces
- decorative complexity
- excessive glow effects
- AI hype aesthetics

Prefer:

- dense but organized tool surfaces
- clear panels and inspectors
- strong typography hierarchy
- predictable navigation
- keyboard-friendly workflows
- fast switching between connections, requests, and responses
- precise raw and structured views of MCP traffic

## Typography and UI Notes

The UI should feel clean, sharp, readable, minimal, and technical.

Guidelines:

- use a dark-first interface
- prefer subtle shadows and gradients
- use strong typography hierarchy
- keep text compact and scannable
- avoid excessive glow effects
- avoid one-note marketing visuals
- keep panels, tables, and inspectors ergonomic for repeated use

## Homepage Direction

The homepage should communicate:

- trust
- developer tooling
- observability
- precision
- infrastructure quality
- open-source positioning

A good first direction is a dark modern landing page centered around an MCP
Inspector dashboard preview, with cyan and purple accents, DevTools-inspired
panels, and a strong focus on inspection and debugging workflows.

The homepage should not look like a generic AI chatbot product.
